01 / 特性

为本地游玩准备的六件事

从下载资源到版本管理，启动器该做的事都在一个界面里，不额外依赖服务端。

01

本地运行

启动器与游戏数据都保存在本机，不需要自建服务器。日常启动已安装的版本时，不依赖任何在线账号系统。

02

安全更新

从 GitHub 检查更新，仅按白名单覆盖启动器自身文件；存档、模组、版本与游戏资源保持原样，绝不覆盖游戏文件。

03

崩溃自检

设置页内置崩溃自检，启动失败后可以快速确认是 Java、内存还是游戏文件的问题，不用对着日志猜。

04

下载检测

设置页提供「下载是否被禁止」检测，帮助排查网络策略或安全软件导致的资源下载失败。

05

国内镜像

内置 BMCLAPI 国内镜像，加速版本清单与游戏资源的下载，在网络受限的环境下更稳定。

06

版本管理

浏览版本清单、下载资源、管理已安装版本，并按需分配内存；一个界面完成全部准备工作。

02 / 更新安全

只动启动器，不动你的游戏

BMCL 从 GitHub 检查新版本。更新过程采用白名单：只替换启动器自身的文件，目录中的存档、模组、整合包与已安装版本不会被写入。

  1. 1
    检查更新

    从 GitHub 获取启动器的最新版本信息。

  2. 2
    白名单比对

    仅将启动器文件列入覆盖范围，其余目录直接跳过。

  3. 3
    覆盖启动器

    更新完成即可继续使用，游戏文件保持原样。

✓

受保护路径

更新时不会覆盖以下内容

  • saves/存档
  • mods/模组
  • versions/版本
  • libraries/依赖库
  • assets/游戏资源
  • options.txt游戏设置

以上路径不在更新覆盖范围内。启动器更新与游戏环境互不影响。

03 / 运行要求

准备一份 Java，然后开始

BMCL 不自带 Java，请在本机安装与游戏版本匹配的 Java 运行时。

Java 版本对照

Minecraft 版本需要的 Java
1.16 及以下Java 8
1.17 及以上Java 17
1.20.5 及以上建议 Java 21

版本越高，对 Java 的要求也越高。装错 Java 是启动失败最常见的原因。

游戏目录

游戏文件默认保存在以下位置：

%APPDATA%\fft1145\game

更新启动器不会修改这个目录里的任何游戏内容。

SmartScreen 提示

portable exe 没有代码签名，首次运行时 Windows 可能显示「Windows 已保护你的电脑」。 确认文件来自 GitHub Releases 后，点击「更多信息」→「仍要运行」即可。

05 / FAQ

常见问题

关于运行方式、更新与安全提示。

BMCL 需要自建服务器或联网吗？

不需要自建服务器。启动器与游戏都完全运行在本地，日常启动已安装的版本不依赖在线服务。首次下载版本清单与游戏资源时需要网络，可借助内置的 BMCLAPI 国内镜像加速；之后可以使用离线登录进入游戏。

更新会覆盖我的存档或模组吗？

不会。更新只覆盖启动器自身文件，并采用白名单机制。saves/、mods/、versions/、libraries/、assets/ 与 options.txt 都在保护范围内，绝不覆盖游戏文件。

启动失败或提示 Java 不对怎么办？

确认本机已安装对应 Java：1.16 及以下用 Java 8，1.17 及以上用 Java 17，1.20.5 及以上建议 Java 21。也可以在设置页使用内置的崩溃自检，逐项确认 Java、内存与游戏文件状态；如果资源下载失败，再运行一次「下载是否被禁止」检测。

Windows 提示「已保护你的电脑」是病毒吗？

这是 SmartScreen 对未签名 portable exe 的常规提示。确认文件来自 GitHub Releases 后，点击「更多信息」→「仍要运行」即可。BMCL 在爱发电发布，不提供任何「定制版」，请以上方 GitHub 与 FFT 主站链接为准。
